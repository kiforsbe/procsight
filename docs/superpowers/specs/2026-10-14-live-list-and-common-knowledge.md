# Live list and common knowledge revision

User-requested scope, 2026-10-14: fix update jitter, broken collapse, generic symbols, and
generic task names; derive provisional roles locally until AI results arrive; ship rules for
known tasks that apply across machines. This extends the approved investigation-only design.

The portable projection preserves prior sibling order during sampling and uses stable group
headers even with one member. Explicit sorting/refresh reorders. Native chevrons own expansion
independently of selection; raw process trees have their own collapsed state. Runtime lifetime
identity remains separate from presentation slots for creation-time-unavailable processes.

Executable icons come from Windows Shell through bounded asynchronous reads and an in-memory
cache. Missing/inaccessible/network paths use a fallback. All HICON/GDI handles are released.

Local labels use service associations, metadata, and known command-role tokens only when the
selected command-line mode allows collection. Specific service/worker roles survive generic
catalog identity labels. Derived labels remain display-only; existing privacy routing applies.

The common catalog is versioned with source and contains 15 attributable purpose definitions.
Matching requires verified signer plus product metadata, or original executable identity and
Windows component path context. Real certificate subjects and `.mui` metadata are supported.
Security/optionality remain unresolved. Learned conflicts and fresh corrections take precedence.
Definitions and their reference links are inspectable; no management actions are introduced.

Verification uses metric changes, group churn, repeated expansion/collapse without reselection,
real executable icon assets, real signed Windows metadata, synthetic roles, and fake providers.
Complete desktop input/accessibility/scaling and live provider checks remain separate acceptance
work; a rendered fixture alone does not establish them.
